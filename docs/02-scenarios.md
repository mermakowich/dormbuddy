## 4. Пользовательские сценарии

### Соседи

Регистрация → профиль → анкета → лента рекомендаций → просмотр совместимости → Like / Skip. Взаимный Like создаёт один Mutual Match. Повторный запрос не создаёт дубликат. После match пользователи видят общие понравившиеся объявления. Пользовательский чат пока не входит в MVP.

### Жильё

Отдельная вкладка → фильтры → карточка квартиры или комнаты → избранное. Можно пользоваться независимо от поиска соседей. Фильтры MVP: стоимость доли аренды, район или метро, тип жилья, допустимость животных и курения. Для объявлений с общей ценой явно показываем число жильцов и расчёт доли; не смешиваем её с ценой всей квартиры.

В MVP используется собственная демонстрационная база Москвы. Объявления явно помечены как учебные, без обещания реальной доступности. Реальные API добавляем после проверки доступности и условий использования; готовность проекта от них не зависит.

### Общежитие

Пользователь выбирает вуз и общежитие → получает потенциальных соседей в этом контексте → сравнивает бытовые привычки → ставит Like. Сервис помогает познакомиться с потенциальным соседом; фактическое заселение и распределение мест остаются за вузом. Интеграции с администрацией общежитий нет.

### AI Buddy

Помощник ведёт диалог и использует доступный контекст: вуз, район или общежитие, бюджет, интересы и этап переезда. Основные сценарии: чек-лист переезда, первые дни в общежитии, организация быта, планирование расходов и досуга.

Примеры: «Что купить в общежитие в первый день?», «Помоги распределить месячный бюджет с учётом аренды», «Составь план первой недели после переезда».

Предлагаем хранить историю диалога и позволить пользователю уточнять запрос. Передаём LLM только необходимый контекст текущего пользователя. Профили других людей, контакты и секреты сервера в запрос не включаем. Актуальные цены, события и маршруты без внешнего источника не представляем как проверенные. При недоступности LLM остальные функции продолжают работать, а помощник сообщает об ошибке и позволяет повторить запрос.
