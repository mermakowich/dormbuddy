## Организация работы

Предлагаем спринты по 1–2 недели. Точные сроки и число спринтов определим после подтверждения дедлайна и доступности участников.

| Этап | Проверяемый результат |
| --- | --- |
| Согласование | Приняты тема, MVP, стек и ответственность участников |
| Проектирование | Product Vision, персоны, User Stories с критериями приёмки и проверкой INVEST, Story Map, CJM, C4 Context, схема БД, нефункциональные требования, backlog |
| Первый рабочий сценарий | Вход → анкета → сохранение в БД → рекомендации с объяснением |
| Расширение MVP | Взаимные лайки, общежития, жильё, избранное и общие варианты |
| Интеграция и защита | AI Buddy, проверки, обработка ошибок, воспроизводимый запуск и демо |

Предлагаем разделить работу на четыре направления. Ответственных определим вместе:

| Направление | Ответственность |
| --- | --- |
| Backend и данные | Авторизация, модели БД, миграции, справочники, согласование API |
| Подбор и взаимодействия | Анкета, алгоритм, объяснения, Like/Skip и mutual match |
| Жильё и интерфейс | Ленты, фильтры, карточки, избранное, связка интерфейса с API |
| Buddy и интеграция | LLM-контекст, история диалога, обработка отказов, сборка сквозного демо |

Если работаем втроём, объединяем направления после оценки нагрузки. Документируем и проверяем свои части; интеграцию, ревью и подготовку защиты делаем вместе. Ответственных и сроки зафиксируем перед первым спринтом.


## Ближайшие решения

- [ ] Принимаем проблему, аудиторию и Москву как пилот.
- [ ] Сохраняем независимые ленты «Соседи» и «Жильё».
- [ ] Принимаем общежитие и AI Buddy как центральные сценарии.
- [ ] Согласуем обязательные поля анкеты и правила расчёта совместимости.
- [ ] Подтверждаем состав MVP и исключения из него.
- [ ] Выбираем frontend и провайдера LLM, определяем доступ к ключу и лимит расходов.
- [ ] Назначаем ответственных, согласуем дедлайн и первый спринт.
- [ ] Передаём краткую концепцию Овчинникову и фиксируем его замечания.
