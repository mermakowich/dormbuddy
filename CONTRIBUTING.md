# Как работать с репозиторием

## Обсуждение

Для вопросов о концепции используем шаблон «Вопрос или решение», для конкретного изменения — «Задача». В описании указываем проблему, предлагаемое решение и затронутые документы. Сложные решения сначала обсуждаем, затем фиксируем в документации.

## Изменения

Работаем в отдельных ветках и открываем pull request на связанное изменение. Например, `docs/mvp-scope` или `feature/matching`. В PR коротко описываем результат и выполненные проверки.

Используем относительные ссылки. Актуальные вложения находятся в `attachments/current`, ранние варианты — в `attachments/archive`. После изменения концепции обновляем README, соответствующий раздел и краткую записку преподавателю.

## Статусы

«В текущей концепции» — основа проекта; «предложение» — вариант, который ещё обсуждаем. Принятые решения фиксируем с датой, согласование преподавателя — по его ответу. Статус реализации указываем отдельно.

## Данные и доступ

Не добавляем пароли, API-ключи, токены, настоящие анкеты пользователей и личные контакты. Для демонстрации используем синтетические данные. Личную переписку, не относящуюся к проекту, в репозитории не храним.

Репозиторий приватный. Доступ, возможное открытие репозитория и лицензию определяем отдельно.
