# DormBuddy — концепция курсового проекта для согласования

**Дисциплина:** «Практикум программирования на Python»  
**Дата:** 2 ноября 2026 года  
**Статус:** предложение темы и границ MVP.

## Идея, аудитория и задача

**DormBuddy** — веб-сервис для студентов, переезжающих учиться в Москву. Он объединяет объяснимый подбор соседей, независимую ленту жилья и AI-помощника по переезду и быту.

Основная аудитория — абитуриенты и студенты первых курсов. Их задача — найти подходящее место для жизни и человека, совместимого по бытовым привычкам, а затем организовать самостоятельный быт.

**Product Vision:** помочь студенту найти соседа, подобрать жильё и освоиться после переезда в рамках одного сервиса. Поиск соседа и жилья доступен параллельно; общежитие — отдельный центральный сценарий.

## Ключевая функция и нетривиальная логика

**Explainable Roommate Matching** — подбор соседей с оценкой совместимости и объяснением результата.

Алгоритм сначала двусторонне проверяет обязательные условия: бюджет для совместной аренды, допустимость курения и животных, вуз/общежитие при включённом ограничении. Затем оценивает сходство бытовых предпочтений: сон, уборка, гости, шум, готовка, общительность.

Для допустимых кандидатов рассчитывается нормированная взвешенная оценка от 0 до 100. Пользователь видит причины результата и расхождения. Пропуски не считаются совпадением; при недостатке данных процент не показывается. Оценка отражает сходство анкет, а не вероятность успешного проживания.

Дополнительная логика: Like/Skip, создание уникального mutual match при взаимной симпатии, пересечение избранных объявлений у совпавшей пары. Расчёт и объяснение совместимости выполняются собственным Python-кодом независимо от LLM.

## Предлагаемый MVP

1. Регистрация, авторизация, профиль и анкета предпочтений.
2. Лента соседей с фильтрацией, score и объяснением совместимости.
3. Like/Skip и mutual match.
4. Режим общежития с выбором вуза и общежития; фактическое распределение мест сервис не выполняет.
5. Параллельная лента квартир и комнат: фильтры, избранное, общие понравившиеся варианты для пары.
6. AI Buddy: диалог через LLM API с контекстом пользователя для планирования переезда, расходов и быта.

Для жилья используем собственную демонстрационную базу Москвы с явной маркировкой учебных объявлений. Реальные API, пользовательский чат, вузовская верификация, монетизация, мобильное приложение и другие города остаются за пределами MVP.

## Техническая реализация и учебная ценность

**Стек:** Python → FastAPI → SQLAlchemy → PostgreSQL; внешний LLM API для Buddy. Простой веб-интерфейс для демонстрации. Архитектура — модульный монолит: Auth, Profiles, Matching, Swipes & Matches, Housing, Dormitories, Buddy.

Основные сущности БД: пользователь, профиль, предпочтения, вуз, общежитие, лайк, совпавшая пара, объявление, избранное, диалог и сообщение Buddy. Предусмотрены внешние ключи, ограничения уникальности, миграции и воспроизводимое заполнение тестовыми данными.

| Ориентир согласования | Как раскрывается в проекте |
| --- | --- |
| Понятные ЦА и ценность | Студенты после переезда; подбор соседа, жилья и помощь с бытом |
| Ключевая функция | Объяснимый алгоритм совместимости, связанный со свайпами |
| Нетривиальная программная часть | Двусторонние ограничения, ранжирование, взаимные лайки, пересечение избранного |
| База данных и API | Связанные сущности, ORM, валидация, авторизация и контроль доступа |
| Объяснимая архитектура | Модули внутри единого приложения, отделение алгоритма от API и LLM |
| Законченный результат | Работающие сквозные сценарии на демонстрационных данных |

Buddy использует контекст текущего пользователя; его недоступность не блокирует matching и ленты. Ключи хранятся на сервере. Проверяем правила подбора, неполные данные, уникальность mutual match, права доступа и обработку ошибок внешнего API.

## Проектирование и демонстрация

После согласования темы подготовим Product Vision, персоны, User Stories по INVEST с критериями приёмки, Story Map, CJM, C4 Context, схему БД, нефункциональные требования и backlog. Планируем итерации по 1–2 недели; распределение работы и календарь уточним по составу команды и дедлайну.

На защите покажем: заполнение анкеты → выдачу с объяснением → взаимный Like → общие варианты жилья; отдельно — режим общежития и ответ Buddy с учётом профиля. Покажем, как конфликт обязательного условия исключает кандидата и как изменение предпочтений влияет на score.
